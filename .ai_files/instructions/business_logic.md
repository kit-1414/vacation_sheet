  # Бизнес логика проекта

  ## Сущьности провета

  ### Пользователь

  Потльзователь (userAccount)
  человек, который логиниться в систему и выполняет в ней нужные действаия.

  Атрибуты пользователя:
  - email  - до 100 символов
    Email — регистронезависимый уникальный идентификатор пользователя.
  - время добавления (задаётся приложением);
  - время редактирования (задаётся приложением);
  - имя - строка до 100 символов;
  - фамилия  - строка до 100 символов.
  - is_admin  - Boolean - признак что пользователь админ
  - is_active - Boolean - признак что пользователь активен.

  ## Проект
  Проект  (Project)- это, Например, проект по разработке продукта.
  он нужен для объединения пользхователей в группы внутри системы. 

  ### Аттрибуты проекта
  Сущность `Project` содержит название, необязательное описание и даты создания и обновления.
  Проекты можно создавать, изменять и удалять.
  Привязка пользователя к проекту выполняется идемпотентным `PUT`, отвязка — `DELETE`.
  Не возвращать JPA-сущности через API; использовать DTO.

  Список аттрибутов проекта

  - Имя — уникальная регистронезависимая строка. Это необходимо учитывать на экранах создания и редактирования.
    Длина: непустая строка от 1 до 100 символов.
    Валидация: допускаются буквенно-цифровые символы а также "-", "." и "_".

  - Комментарий — любые символы.
    Длина: от 0 до 1000 символов.
    Валидация: любые символы.

  ### Связи Проекта
  Проект имеет 2 связи c пользователями:
  - `Project` связан с `UserAccount` отношением "Участник проекта" (member) many-to-many через таблицу `project_members`".
  - `Project` связан с `UserAccount` вторым отношением "Рководитель проекта" (Manager) many-to-many через таблицу `project_manager`.

  #### Руководители проектов
  Описываем логику связиРуководитель проекта Проекта и пользователя системы -
  Пользователь является руководителем(менеджером), если есть хотя бы 1 проект, где он руководитель. 

  - Данная связь даёт доступ к функциональности руководства проектами (будет описано в документации фронтенда).
  - Назначение пользователя руководителем выполняется аналогично добавлению как участника.
  - Не возвращать JPA-сущности через API; использовать DTO.

  ## Добавление Пользователи при логине
  - При первом успешном OAuth2-входе сохранять пользователя в PostgreSQL: `lower(email)`, имя и фамилию.
  - При последующих входах идентифицировать пользователя по `lower(email)`, но больше ничего не менять.
  - Внешним ключом идентификации служит `lower(email)`.

  ## Пользователи и Роли
   Каждому залогиненому пользовалелю назначается 1..N ролей
  - NOBODY  - user.isActive = false
  - АDMIN   - user.isActive = true && user.isAdmin = true 
  - MANAGER - user.isActive = true и пользователь я вляется руководителем(менеджером)
  - USER    - user.isActive = true и он не руководитель
   
  Роли присваявать на этапе логина. Дальше не проверять.

   Роль АDMIN дает доступ ко всем страницам и действиям в системе. 
   При любом перечне ролей на разрешение чего либо админдобавляется в этот список по умолчанию.
  
   Если для страницы, списка или ссылки не прописаны явно запреты или правила - они разрешены для любой роли.
   
   Термин "Активен" - в описании экранов встречается термин "активен" для некой роли(ролей).
   Это значит что для упомянутых роле доступен переход или действие, для остальных - тролько текст (или конока неактивна)

   В коде бэкенда роли представлены
     - констнтами - литералами
     - енумом, со свойством roleName т этих литералов
   

  ## Действия пользователя в системе

  ### Удаление пользователей и проектов

  - При удалении пользователя удаляются только пользователь и его связи с проектами.
  - При удалении проекта удаляются только проект и его связи с пользователями.

  ## Структура фронтенда

  ### Главное меню

  После входа фронтенд показывает главное верхнее меню. Меню содержит:

  - email текущего пользователя;
  - кнопку выхода пользователя;
  - ссылку на список проектов;
  - ссылку на список пользователей системы.

  #### Работа с пользователями

  Пользователи появляются в системе при входе через Яндекс. Пользователи добавляются двумя способами:

  1. При входе, если пользователя ещё нет в системе, email, имя и фамилия берутся из OAuth-атрибутов.
  1.1. если пользователь первый в  системе, то он становится админом
  1.2 пользователь добавляется isActive=true. 
  2. На странице добавления нового пользователя.

  #### Страница «Список пользователей»
  Доступна к просмотру для любой роли.

  Страница содержит
  - список пользователей системы с атрибутами
  - кнопку перехода на страницу «Добавление пользователя» - активна только для роди ADMIN
  - возможность удалить выбранных пользователей -  активна только для роди ADMIN
  - ссылки на страницы редактирования пользователей - активна только для роди ADMIN

  #### Страница «Добавление пользователя»
  Страница доступна только для роли ADMIN
  Страница добавляет нового пользователя.

  #### Страница «Редактирование пользователя»
  Страница доступна только для роли ADMIN
  Страница позволяет редактировать атрибуты существующего пользователя.

  ### Работа с проектами

  #### Страница "Список проектов"
  Доступна к просмотру для любой роли.
  Страница содержит 
   - список проектов (`Projects`) в виде таблицы
   - возможность удалить выбранные проекты и кнопку создания нового проекта. - активна только для роли ADMIN

  В списке (таблице) показываются атрибуты проектов (и только они):
  - имя
  - время добавления
  - "Команда" в виде числа - кв-во участников проекта
  - «Руководители» в виде числа - кв-во руководителей проекта
  - первые 40 символов комментария;
  - ссылка на страницу редактирования проекта - активна только для роли ADMIN
  - ссылка на страницу «Участники/Руководители проекта» - активна только для роли MANAGER
    Заголовок колонки - текст «Участники/Руководители»
    текст ссылки-кнопки -  «Назначить»

  #### Страница «Создать проект»
  Страница доступна только для роли ADMIN
  Страница позволяет создать новый проект, задав:
  - имя
  - комментарий

  #### Страница «Редактировать проект»
  Страница доступна только для роли ADMIN
  Страница позволяет отредактировать проект, изменив:
  - имя
  - комментарий

  #### Страница «Участники/Руководители проекта»
  Страница доступна для роли Manager
  Страница позволяет добавлять и удалять участников проекта через ссылку в колонке "Команда проекта".
  Страница позволяет добавлять и удалять руководителей проекта через ссылку в колонке «Руководители проекта».
  В списке пользователей необходимо показывать email, имя и фамилию. Список можно сортировать по одной любой колонке и фильтровать по любой колонке с использованием условия `LIKE '%<pattern>%'`.
