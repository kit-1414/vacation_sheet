# Бизнес-логика проекта

## Сущности проекта

### Пользователь

Пользователь (`UserAccount`) — человек, который входит в систему и выполняет в ней необходимые действия.

#### Атрибуты пользователя

- Email — строка длиной до 100 символов. Регистронезависимый уникальный идентификатор пользователя;
- время добавления — задаётся приложением;
- время редактирования — задаётся приложением;
- имя — строка длиной до 100 символов;
- фамилия — строка длиной до 100 символов;
- `is_admin` (`Boolean`) — признак того, что пользователь является администратором;
- `is_active` (`Boolean`) — признак того, что пользователь активен.

### Проект

Проект (`Project`) — например, проект по разработке продукта. Он нужен для объединения пользователей в группы внутри системы.

Сущность `Project` содержит название, необязательное описание, а также даты создания и обновления. Проекты можно создавать, изменять и удалять.

Привязка пользователя к проекту выполняется идемпотентным запросом `PUT`, отвязка — запросом `DELETE`.

Не возвращать JPA-сущности через API; использовать DTO.

#### Атрибуты проекта

- Имя — уникальная регистронезависимая строка. Это необходимо учитывать на экранах создания и редактирования.
  Длина: непустая строка от 1 до 100 символов.
  Валидация: допускаются буквенно-цифровые символы, а также `-`, `.` и `_`.
- Комментарий — строка из любых символов длиной от 0 до 1000 символов.

#### Связи проекта

Проект имеет две связи с пользователями:

- `Project` связан с `UserAccount` отношением «Участник проекта» (`member`) many-to-many через таблицу `project_members`;
- `Project` связан с `UserAccount` отношением «Руководитель проекта» (`manager`) many-to-many через таблицу `project_manager`.

#### Руководители проектов

Пользователь является руководителем (менеджером), если он руководит хотя бы одним проектом.

- Эта связь даёт доступ к функциональности руководства проектами, описанной в документации фронтенда.
- Назначение пользователя руководителем выполняется аналогично добавлению участника.
- Не возвращать JPA-сущности через API; использовать DTO.

## Добавление пользователей при входе

- При первом успешном OAuth2-входе сохранять в PostgreSQL email пользователя в нижнем регистре (`lower(email)`), его имя и фамилию.
- При последующих входах идентифицировать пользователя по `lower(email)`, но больше ничего не изменять.
- Внешним ключом идентификации служит `lower(email)`.

## Пользователи и роли

Каждому вошедшему в систему пользователю назначается от одной до нескольких ролей:

- `NOBODY` — `user.isActive = false`;
- `USER` — `user.isActive = true`;
- `MANAGER` — `user.isActive = true`, и пользователь является руководителем (менеджером);
- `ADMIN` — `user.isActive = true && user.isAdmin = true`.

Роль `ADMIN` даёт доступ ко всем страницам и действиям в системе. При любом перечне ролей, которым разрешено действие, `ADMIN` добавляется в этот список по умолчанию.

Если для страницы, списка или ссылки явно не описаны запреты или правила, они доступны любой роли.

Термин «активен» в описании экранов означает, что для указанных ролей доступен переход или действие. Для остальных ролей отображается только текст либо неактивная кнопка.

В коде бэкенда роли представлены:

- константами-литералами;
- перечислением (`enum`) со свойством `roleName`, содержащим соответствующий литерал.

## Доступ к текущему пользователю и ролям

Для работы с текущим пользователем и его ролями использовать отдельные DTO и сервис, а также метод `CurrentUserService.getCurrentUser(): CurrentUserDto`.

Использовать этот сервис и DTO:

- в контроллере `*/me`;
- в контроллерах и сервисах, где требуется проверить принадлежность сущности текущему пользователю, передавая DTO в сервис в качестве параметра.

### Заявление на отпуск

Заявление на отпуск (`vacation_request`) создаётся и редактируется пользователем. Затем оно согласовывается (`approve`) или отклоняется (`reject`) руководителем.

#### Атрибуты заявления на отпуск

- заголовок (`title`) — текст длиной до 50 символов;
- состояние (`request_state`, `enum`): черновик (`DRAFT`), готово (`READY`), одобрено (`APPROVED`), отклонено (`REJECTED`);
- вид отпуска (`vacation_type`, `enum`): оплачиваемый отпуск (`PAYMENT_VACATION`), отпуск за свой счёт (`FREE_VACATION`);
- дата начала отпуска;
- дата завершения отпуска;
- комментарий пользователя (`user_comments`) — текст длиной до 2000 символов;
- комментарий руководителя (`manager_comments`) — текст длиной до 2000 символов.

#### Связи заявления на отпуск

- связь с создателем-заявителем (`author_id`) — many-to-one с пользователем, устанавливается при создании;
- связь с руководителем (`manager_id`) — many-to-one с пользователем, устанавливается при одобрении или отклонении.

#### Политика действий с заявлениями на отпуск

Методы работы с заявлениями разделены на группы по ролям.

##### Методы для пользователя

Для пользовательских операций реализовать отдельные методы по адресу `/user/actions/vacation_request/*`: получение списка заявлений, создание, редактирование и удаление.

Для получения списка в `VacationRequestService` должен быть метод `getRequestsByOwnerId(id): List<VacationRequest>`.

На бэкенде:

- получение заявления по ID доступно всем пользователям;
- при изменении или удалении заявления по ID необходимо дополнительно проверять, что оно принадлежит текущему пользователю.

В `VacationRequestService` должны быть методы проверки авторства заявления:

- `checkIsCreator(requestVacationId, CurrentUserDto): Boolean`;
- `failIfNotCreator(requestVacationId, CurrentUserDto)` — выбрасывает исключение об отказе в доступе и записывает на уровне DEBUG сообщение на английском языке о попытке доступа к чужому заявлению.

Автор может обновлять и удалять заявление только в состояниях `DRAFT` или `READY`.

##### Методы для руководителя

Для операций руководителя по рассмотрению заявлений реализовать отдельные методы по адресу `/manager/actions/vacation_request/*`.

Операции рассмотрения заявления по ID выполняются руководителями проектов отдельными методами и не требуют проверки принадлежности заявления текущему пользователю.

Операция рассмотрения возможна только для заявления в одном из состояний: `READY`, `APPROVED`, `REJECTED`.

Метод позволяет:

- сменить состояние заявления с любого разрешённого состояния на любое другое разрешённое состояние;
- отредактировать комментарий руководителя, не меняя состояние заявления.

При переводе заявления в состояние `READY` связь с руководителем и комментарий руководителя очищаются.

Метод рассмотрения заявления:

- принимает `vacationRequestId` в path;
- принимает JSON следующего вида:

```json
{
  "managerComment": "<комментарий руководителя или null>",
  "updateManagerComment": true,
  "requestState": "<READY | APPROVED | REJECTED>"
}
```

Поле `updateManagerComment` определяет, нужно ли обновлять комментарий руководителя значением `managerComment`:

- при `updateManagerComment = false` текущее значение комментария сохраняется;
- при `updateManagerComment = true` комментарий обновляется значением `managerComment`;
- при `managerComment = null` и `updateManagerComment = true` комментарий очищается;
- при переводе заявления в состояние `READY` руководитель и его комментарий очищаются независимо от значений `managerComment` и `updateManagerComment`.

Метод получения заявления на рассмотрение по ID:

- принимает `vacationRequestId` в path;
- возвращает заявление с автором, руководителем и проектами автора по связи `project_members`;
- не возвращает заявления в состоянии `DRAFT`.

##### Общий метод получения полного списка заявлений

Необходимо реализовать отдельный метод получения полного списка заявлений на отпуск. Метод доступен всем пользователям. В список не должны попадать заявления в состоянии `DRAFT`.

##### Методы для администратора

Для операций администратора реализовать отдельные методы по адресу `/admin/actions/vacation_request/*`: получение списка заявлений, создание, редактирование и удаление.

При реализации необходимо проверять на бэкенде, что текущий пользователь является администратором.

Пока не реализовывать методы администратора без отдельной необходимости на бэкенде.

## Действия пользователя в системе

### Удаление пользователей и проектов

- При удалении пользователя удаляются только пользователь и его связи с проектами.
- При удалении проекта удаляются только проект и его связи с пользователями.

## Структура фронтенда

### Главное меню

После входа фронтенд показывает главное верхнее меню. Меню содержит:

- email текущего пользователя;
- кнопку выхода;
- ссылку на список проектов;
- ссылку на список пользователей системы;
- ссылку на страницу личного кабинета пользователя.

#### Работа с пользователями

Пользователи появляются в системе при входе через Яндекс. Пользователи добавляются двумя способами:

1. При входе, если пользователя ещё нет в системе, email, имя и фамилия берутся из OAuth-атрибутов.
   Если это первый пользователь в системе, он становится администратором. Пользователь добавляется с `isActive = true`.
2. На странице добавления нового пользователя.

#### Страница «Список пользователей»

Страница доступна для просмотра любой роли и содержит:

- список пользователей системы с их атрибутами;
- кнопку перехода на страницу «Добавление пользователя», активную только для роли `ADMIN`;
- возможность удалить выбранных пользователей, активную только для роли `ADMIN`;
- ссылки на страницы редактирования пользователей, активные только для роли `ADMIN`.

#### Страница «Добавление пользователя»

Страница доступна только для роли `ADMIN` и позволяет добавить нового пользователя.

#### Страница «Редактирование пользователя»

Страница доступна только для роли `ADMIN` и позволяет редактировать атрибуты существующего пользователя.

### Работа с проектами

#### Страница «Список проектов»

Страница доступна для просмотра любой роли и содержит:

- список проектов (`Projects`) в виде таблицы;
- возможность удалить выбранные проекты и кнопку создания проекта, активные только для роли `ADMIN`.

В таблице отображаются только следующие атрибуты проектов:

- имя;
- время добавления;
- «Команда» — количество участников проекта;
- «Руководители» — количество руководителей проекта;
- первые 40 символов комментария;
- ссылка на страницу редактирования проекта, активная только для роли `ADMIN`;
- ссылка на страницу «Участники/Руководители проекта», активная только для роли `MANAGER`. Заголовок колонки — «Участники/Руководители», текст ссылки-кнопки — «Назначить».

#### Страница «Создать проект»

Страница доступна только для роли `ADMIN` и позволяет создать проект, указав:

- имя;
- комментарий.

#### Страница «Редактировать проект»

Страница доступна только для роли `ADMIN` и позволяет изменить:

- имя;
- комментарий.

#### Страница «Участники/Руководители проекта»

Страница доступна для роли `MANAGER`.

Страница позволяет:

- добавлять и удалять участников проекта через ссылку в колонке «Команда проекта»;
- добавлять и удалять руководителей проекта через ссылку в колонке «Руководители проекта».

В списке пользователей необходимо показывать email, имя и фамилию. Список можно сортировать по одной любой колонке и фильтровать по любой колонке с помощью условия `LIKE '%<pattern>%'`.

### Страница «Личный кабинет»

Страница доступна всем и содержит информацию о текущем пользователе:

- email;
- имя;
- фамилия;
- время добавления в систему;
- время последнего обновления данных пользователя.

Страница содержит:

- ссылку на страницу «Мои заявления на отпуск»;
- ссылку на страницу «Все заявления на отпуск».

### Работа с заявлениями на отпуск: создание и редактирование

#### Страница «Мои заявления на отпуск»

Страница доступна всем.

Страница содержит кнопку «Добавить заявление на отпуск» для создания нового заявления. Кнопка активна для роли `USER`.

Страница содержит список заявлений на отпуск текущего пользователя в виде таблицы со следующими данными и действиями:

- заголовок;
- время создания;
- состояние запроса;
- тип отпуска;
- ссылка на редактирование заявления, активная для роли `USER` при состояниях `DRAFT` и `READY`;
- кнопка удаления заявления, активная для роли `USER` при состояниях `DRAFT` и `READY`.

Доступна сортировка:

- по времени создания;
- по дате начала;
- по дате завершения.

Доступна фильтрация:

- по состоянию заявления;
- по типу отпуска.

#### Страница «Добавить заявление на отпуск»

Страница доступна для роли `USER`.

На странице отображаются следующие атрибуты:

- email;
- имя автора;
- фамилия автора;
- заголовок;
- дата начала отпуска;
- дата завершения отпуска;
- комментарий автора;
- тип отпуска;
- состояние запроса, доступное для изменения;
- комментарий руководителя, доступный для редактирования.

#### Страница «Редактировать заявление на отпуск»

Страница доступна для роли `USER`.

Автору заявления всегда отображается ссылка «Редактировать». Заявления в состоянии `READY` открываются в режиме редактирования. Заявления в состояниях `APPROVED` и `REJECTED` открываются в режиме только для чтения: поля и кнопка сохранения заблокированы, а на странице отображается пояснение о невозможности изменения заявления в текущем состоянии.

#### Страница «Просмотреть заявление на отпуск»

Страница доступна всем и позволяет просмотреть атрибуты заявления без возможности изменения.

### Страница «Все заявления на отпуск»

Страница доступна всем пользователям и содержит список всех заявлений на отпуск, кроме заявлений в состоянии `DRAFT`, с возможностью фильтрации и сортировки.

Страница доступна по адресу `/profile/vacation-requests/review`.

Страница содержит ссылку на страницу «График заявлений на отпуск». При переходе сохраняются фильтры и сортировка, чтобы восстановить состояние страницы после возвращения.

Если текущий пользователь является руководителем, страница позволяет изменить состояние заявления без изменения комментария.

Таблица содержит следующие данные и действия:

- заголовок;
- email автора — доступны сортировка и фильтрация;
- имя автора — доступны сортировка и фильтрация;
- фамилия автора — доступны сортировка и фильтрация;
- количество проектов автора по связи `project_members`;
- время создания — доступна сортировка;
- дата начала отпуска — доступна сортировка;
- дата завершения отпуска — доступна сортировка;
- состояние заявления — доступны сортировка и фильтрация, а руководителю доступно изменение состояния;
- тип отпуска;
- ссылка «Рассмотреть» на страницу «Рассмотреть заявление на отпуск с комментарием». Для руководителя ссылка активна, если доступно изменение состояния; в остальных случаях ссылка неактивна;
- ссылка «Редактировать» на страницу редактирования заявления, если текущий пользователь является его создателем, либо ссылка «Просмотреть» на страницу просмотра заявления, если текущий пользователь не является его владельцем.

В каждый момент времени сортировка возможна только по одному из указанных в перечне атрибутов, по возрастанию или убыванию. Ссылка для сортировки располагается в заголовке соответствующей колонки.

Доступна следующая фильтрация:

- по email, имени и фамилии автора — регистронезависимое вхождение;
- по интервалу дат — отпуск должен хотя бы одним днём попадать в заданный интервал. Допускается открытый интервал, в котором указана только одна дата;
- по набору проектов — множественный выбор из списка всех проектов системы с помощью флажков. Для соответствия фильтру достаточно пересечения по одному проекту;
- по состоянию заявления. При открытии страницы по умолчанию выбраны состояния `READY` и `APPROVED`.

Блок фильтров располагается слева, список заявлений — справа.

В блоке фильтров сверху находятся кнопки
 - "Сбросить все фильтры"
 - "Текущие отпуска".


По нажатию книопки "Сбросить все фильтры": 
 - в фильтрах все текущие значения фильтров сбрасываются. 
 - Пагинация и сортировки не меняются

По нажатию книопки "Текущие отпуска":
 - сбрасыватся фильтры (как на кнопке "Сбросить все фильтры")
 - в фильтрах выставляются значения:
    - начало и конец отпуска - текущий день по локали браузера
    - состояние заявления - одобрено.


Для таблицы добавить пагинацию с изменяемым размером страницы: 10, 50, 100 или 300 заявлений.

### Страница «Рассмотреть заявление на отпуск с комментарием»

Страница доступна только для роли `MANAGER`.

Страница отображает атрибуты заявления на отпуск в режиме только для чтения, а также список проектов, в которых участвует пользователь. Состояние заявления и комментарий руководителя доступны для редактирования и при загрузке содержат текущие значения.

На странице отображаются:

- заголовок заявления;
- email, имя и фамилия автора;
- комментарий автора;
- время последнего изменения;
- время создания;
- даты начала и завершения отпуска;
- тип отпуска;
- состояние заявления (`request_state`);
- комментарий руководителя;
- список проектов автора заявления по связи `project_members`.

Страница позволяет изменить состояние заявления и комментарий руководителя.

На странице есть кнопка возврата на страницу «Все заявления на отпуск».

### Страница «График заявлений на отпуск»

Страница доступна всем пользователям.

Страница доступна по адресу `/profile/vacation-requests/review/schedule`.

Страница «Все заявления на отпуск» содержит ссылку на график. При переходе на график сохраняются фильтры, сортировка и пагинация родительской страницы. При возврате из графика состояние родительской страницы восстанавливается. Состояние сохраняется до перезагрузки SPA.

График получает весь отфильтрованный и отсортированный список заявлений родительской страницы до применения пагинации.

Оси графика:

- сотрудники перечислены строками по вертикали;
- календарные дни расположены колонками по горизонтали;
- слева располагается фиксированная колонка с данными сотрудника;
- временная шкала имеет горизонтальную прокрутку.

Порядок сотрудников соответствует порядку их первого появления в отфильтрованном и отсортированном списке заявлений родительской страницы.

Если у одного сотрудника есть пересекающиеся заявления, они отображаются в отдельных подстроках одной строки сотрудника. Непересекающиеся заявления могут использовать одну подстроку.

Заявление отображается горизонтальным прямоугольником. Его положение соответствует дате начала, а длина — продолжительности отпуска. Часть заявления, выходящая за отображаемый календарный диапазон, обрезается.

Цвет прямоугольника зависит от состояния заявления:

- `READY` — синий;
- `APPROVED` — зелёный;
- `REJECTED` — красный.

На странице отображается легенда цветов. Для заявления доступна подсказка с заголовком, автором, датами, типом отпуска и состоянием.

Текущий день расположен в центре временного диапазона и визуально выделен. Пользователь задаёт количество дней в каждую сторону от текущего дня.
текущий день выделен вертикально по всей высоте грефика. 
Значение по умолчанию — 183 дня. Допустимый диапазон — от 1 до 366 дней. 
После открытия страницы и изменения значения график прокручивается к текущему дню.

Заголовок графика содержит:

- группировку дней по месяцам;
- день недели и число месяца для каждой дневной колонки;
- визуальное отличие выходных дней от рабочих.

Щелчок правой или левой кнопкой мыши по заявлению на настольном устройстве либо обычный щелчок или касание на сенсорном устройстве открывает меню ссылок:

- «Рассмотреть заявление» — ссылка активна, если текущий пользователь является руководителем. Она открывает модальное окно рассмотрения заявления. 
  В модальном окне отображаются данные заявления и проекты автора. Руководитель может изменить состояние и комментарий по тем же правилам, 
  что и на странице «Рассмотреть заявление на отпуск с комментарием». После успешного сохранения график обновляется без перезагрузки страницы. 
   Если новое состояние не соответствует сохранённому фильтру родительской страницы, заявление исключается из графика. Страница содержит ссылку возврата на страницу «Все заявления на отпуск»

- «Редактировать» или «Просмотреть» — ссылка открывает модальное окно редактирования заявления автором (Если состояние позволяет) либо просмотра заявления.
